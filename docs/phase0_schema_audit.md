# Phase 0 — Earnings persistence schema audit

**Status:** Phases 0–5 complete. Phase 6's staging-isolation config, safety-guarded pilot script, and acceptance runbook are implemented; the actual write pilot/rollout remains pending an isolated staging MongoDB endpoint.

**Compared:** this repository's `integrations/normalize.py`, `state.py`, and save pipeline against Gotham's `normalization/src/data_normalization_service/core/models.py`, `services/normalization_service.py`, `services/quarterly_service.py`, and historical SEC client/CLI.

## 1. Collection routing

| Purpose | Earning-agent collection | Current route |
|---|---|---|
| Annual concepts | `normalized_concepts_annual` | `DetectedPeriod.period_type == "annual"` |
| Quarterly concepts | `normalized_concepts_quarterly` | `DetectedPeriod.period_type == "quarterly"` |
| Annual values | `concept_values_annual` | `DetectedPeriod.period_type == "annual"` |
| Quarterly values | `concept_values_quarterly` | `DetectedPeriod.period_type == "quarterly"` |

The route is centralized in `_concepts_collection(period)` and `_values_collection(period)`. `get_statement_concepts()` itself queries **only the collection selected by the filing period**. For quarterly runs, `load_company_concepts_node()` now bootstraps the quarterly concept collection from annual concepts first, but only when the company has no quarterly concept rows at all. This does not read annual values as quarterly values.

Gotham also separates annual and quarterly concept/value collections. Its normalization service routes repositories by filing form type, while this repository routes by the canonical agent-detected period. The implementation should preserve period-agent routing and use an explicit source-form field rather than use `6-K` to select annual versus quarterly collections.

## 2. Current concept read contract

`get_statement_concepts()` reads these source fields when available:

- `_id` — converted to a string for the extraction target and later back to `ObjectId` for value persistence.
- `cik`, `statement_type`, `concept`, `label`, `path`, `order_key`.
- `dimension`, `dimension_concept`, and `calculated`.
- Additional label/member data is derived for the prompt, including `taxonomy_key`, `dimension_member`, `dimension_member_label`, and `dimension_axis`.

The normalized target is therefore a *view* of concept documents, not a verbatim copy of Gotham's `ConceptDocument`. Gotham's model also represents `canonical_concept`, `form_type`, `abstract`, `hide`, `parent_concept`, `parent_path`, `parent_concept_id`, `parent_header`, and richer dimensional metadata. During the Phase 1 bootstrap, annual concept documents are copied with their existing `_id` and metadata, changing `form_type` to `10-Q`; preserving IDs keeps copied parent and dimensional references valid within the quarterly collection.

The extraction prompt's `taxonomy_key` is generated by this repository and can be path-qualified to disambiguate repeated concepts. It should not be treated as a Mongo `_id` or as proof that two concepts in separate collections have the same identity. Prefer exact concept/taxonomy identity, then an approved canonical/alias mapping; labels alone are insufficient for cloning.

## 3. Current value write contract

`upsert_concept_values()` writes one document per extracted concept to the period-routed value collection. The current document contains:

| Field | Current behavior |
|---|---|
| `concept_id` | BSON `ObjectId` made from the selected concept row's `_id` |
| `cik`, `statement_type` | Company and statement identity |
| `form_type` | Synthetic `10-Q` for quarterly, `10-K` for annual; **not** the source SEC form |
| `reporting_period.end_date` | UTC midnight `datetime` |
| `reporting_period.period_date` | `YYYY-MM-DD` string |
| `reporting_period.fiscal_year` | Canonical period-agent year |
| `reporting_period.quarter` | Quarterly only |
| `reporting_period.start_date` | Quarterly only, when parsed from the period label |
| `value`, `created_at` | Extracted/scaled number and write timestamp |
| `earning_data` | `True` |
| `dimension_value`, `dimension_member`, `dimension_member_label`, `dimension_axis` | Dimensional metadata when supplied |
| `calculated` | Derived status |
| `currency` | The value's confirmed ISO currency (USD preferred, otherwise the filing's reported currency). No default: a value whose currency is unconfirmed is not written. |
| `accession_number` | Included when known |
| `save_token` | Supports write-first atomic replacement and stale sweep |
| `original_currency`, `original_value`, `original_scale` | Optional, only when supplied in metadata |
| `source_exhibit`, `extraction_status` | Optional metadata fields |
| `scale`, `source_lines`, `source_snippet` | Per-value extraction evidence; now serialized by the Phase 2 writer |

The value identity/filter is `(cik, concept_id, reporting_period.fiscal_year[, reporting_period.quarter])`; dimensions are metadata and are not part of that filter. Annual documents omit quarter and start date. Quarterly Q4 is not a quarterly filing period; Q4 is stored through the annual path and has separate post-save derivation behavior.

### Important audit findings to resolve in implementation phases

1. The value writer's `form_type` currently means normalized period family (`10-Q`/`10-K`), unlike Gotham's `ValueDocument.form_type`, which is the source filing form (for example `10-Q`, `20-F`). Do not overwrite this field with `6-K` without auditing current consumers. The compatible first step is an additive `source_form_type` field; a later shared contract can introduce an explicit `period_type` and migrate readers.
2. Resolved in Phase 3: the value writer no longer defaults to USD. It writes only a confirmed ISO currency; unconfirmed values are skipped by the writer and dropped earlier by the pipeline/save node.
3. Resolved in Phase 2: `upsert_concept_values()` now serializes per-value `scale`, `source_lines`, and `source_snippet` when supplied by extraction evidence. Older value documents may not contain these optional fields.
4. Gotham's `ValueDocument` preserves `fact_id`, `decimals`, `source`, and `accession_number`, but its dataclass does not define the earning-agent's `currency`, `scale`, `source_lines`, or `save_token`. Conversely, the earning-agent writer does not currently persist Gotham's `fact_id`, `decimals`, or `source` fields. Treat these as a schema gap to bridge, not as an existing identical contract.
5. Phase 2 adds a save-gated concept-creation path for agent-proposed filing rows that remain unmapped after exact and high-confidence semantic mapping. It creates/reuses a period-specific company concept with a parent selected from the target hierarchy, then saves the filing value against its ID. Invalid/missing evidence or unresolved parents leave that candidate unsaved without blocking other mapped values.
6. Gotham's quarterly helper searches quarterly concepts first and then annual concepts. This pipeline implements the requested company-level all-or-nothing bootstrap separately: when quarterly concepts are completely absent for a CIK, it copies all annual concept documents before the normal quarterly lookup. It preserves IDs and metadata, changes `form_type` to `10-Q`, and copies no annual values.

### Bookkeeping collections: none

The project persists only to `normalized_concepts_{quarterly|annual}`,
`concept_values_{quarterly|annual}`, and `companies`. `earnings_backfill_ledger` and
`quarterly_concept_bootstrap` were both removed and must not be recreated:

* backfill resume reads `accession_number` from the saved value documents
  (`backfill.processed_accessions`);
* the quarterly concept bootstrap treats the quarterly concept collection itself as its
  state (`$setOnInsert` makes a rerun harmless).

`tests/test_no_bookkeeping_collections.py` enforces this with a static scan of `src/` and
a guarded Mongo client that raises on any collection outside the allowed set.

## 4. Target compatibility contract and implementation status

- Period type controls collection routing: annual versus quarterly.
- `source_form_type` records the SEC source form (`6-K`, `8-K`). Keep legacy `form_type` semantics until dependent readers are migrated. **Implemented in Phase 4:** the shared state builder sets it from the requested form / discovered form / worker payload, and the value writer persists it additively (guidance uses it as the doc `form_type`). The synthetic period-family `form_type` (`10-Q`/`10-K`) is unchanged.
- A value is linked only to a concept row in the matching period collection.
- **Implemented in Phase 1 — quarterly concept bootstrap is company-level and all-or-nothing:** before normal quarterly concept loading, check whether `normalized_concepts_quarterly` has any concept rows for the CIK. Only when it has none, bulk-copy all of that company's annual concept rows into the quarterly collection. If quarterly rows already exist for the company—even if some statements or concepts are missing—do not run this annual bootstrap; continue with the existing quarterly universe.
- The bootstrap copies concept definitions, not annual values. It copies annual concept documents into the separate quarterly collection with their existing `_id` and metadata, changing `form_type` to `10-Q`. Keeping IDs also keeps copied `parent_concept_id` and dimensional concept references valid. Bulk `$setOnInsert` operations make reruns idempotent, and there is no bookkeeping collection — the quarterly concept collection itself is the bootstrap state. The extraction agent then runs against the quarterly collection as it does now, and only filing-derived quarterly values are saved.
- **Implemented in Phase 2 — new concepts:** the extraction agent can propose a grounded printed value after `map_concept()` finds no existing match. Exact and high-confidence semantic mapping run first; only still-unmapped candidates with valid evidence, a targeted statement, and an exact existing parent or explicit root are eligible. The save node creates/reuses a stable `custom:` concept in the filing-period collection after the normal save gates pass, materializes an appended path/order key, then saves the value. Candidate failures do not block existing mapped values. Computed concepts are not created, and new cash-flow concepts from YTD Q2/Q3 statements are omitted until de-accumulation supports unpersisted concepts.
- **Implemented in Phase 3 — currency:** USD is preferred when the filing presents a USD column/table for a statement; otherwise the filing's reported native currency is persisted as-is. There is no FX conversion and no unknown-to-USD default. The pipeline resolves ONE confirmed ISO currency per statement and drops values that cannot be attributed to it (medium-severity observability), so a statement is never stored as a currency mix. Per-value `__evidence__[*].currency` overrides the document-level default. Q4 derivation only combines same-currency inputs (a mismatch or an unconfirmed annual/quarterly currency skips that concept, never converts). Guidance follows the same rule and beat/miss scoring only compares matching currencies — a confirmed mismatch leaves the doc unscored. The save node applies the same rule as a write-time backstop.
- Preserve accession, calculation status, scale/currency evidence, dimension identity, and extraction provenance where available. Scale and line/snippet evidence are now persisted by the value writer.
- Values from differing currencies must not be combined in derived arithmetic or presented as a comparable currency series without an explicit conversion policy.

## 4b. 6-K ingestion (Phase 4)

- `get_latest_filing_url(cik, forms)` generalizes discovery to 8-K + 6-K and returns the resolved form; `get_latest_earnings_url(cik)` stays an 8-K-only wrapper with unchanged behavior.
- A 6-K is only auto-selected when its filing-index EX-99 description/filename looks like an earnings release (at most 5 recent 6-Ks are inspected). Unrelated 6-Ks are never silently fed into the earnings pipeline.
- The reliable path is a pinned accession: `get_exhibits_for_accession` already resolves any form's index from the exact accession. `get_filing_form_type` records provenance for a pinned accession when the caller does not supply the form.
- Period identity remains agent-owned: the period prompt now states that the source may be a 6-K with varied label conventions and that the form never determines the period.
- The worker accepts `8-K` and `6-K` payloads (`_SUPPORTED_FORMS`) on its existing queue and still rejects other forms without re-queuing.
- Existing behavior is preserved: default discovery still calls the 8-K-only path, so US-issuer runs are unchanged.
- `_parse_filing_index` now recognizes the PRIMARY document row for any supported source form (`6-K`, `10-Q`, ...), not just `8-K`. Previously a 6-K whose index has no EX-99 exhibit (TSM's monthly-revenue 6-Ks) resolved to *zero* documents; the pinned-accession path now correctly falls back to the 6-K primary document.

### Read-only live validation (ASML / TSM, 2026 filings)

- **ASML** auto-discovery selects the earnings 6-K (`0001628280-26-048235`, 2026-07-15) and correctly skips the earlier 6-K whose only exhibit is the AGM-results notice. Its earnings exhibits are `pressreleasefinancialresul.htm` (EX-99.1), `presentationinvestorrela.htm` (EX-99.2), `financialstatementsusgaa.htm` (EX-99.3).
- **TSM** auto-discovery returns nothing, which is the intended safe outcome: its earnings exhibits are named opaquely (`a2q26e_withguidancexfinal.htm`) and its monthly-revenue 6-Ks carry no EX-99 exhibit, so the metadata filter cannot positively identify an earnings release. TSM must use a pinned accession (`0001046179-26-000451` for 2Q26) or a manual URL.

## 5. Historical extraction boundary — implemented (Phase 5)

`get_company_filings()` reads ``filings.recent`` **and** every ``filings.files[]``
pagination page (skipping pages whose ``filingTo`` predates the requested range),
so ranges older than the submissions window are reachable.
`build_earnings_manifest()` turns that history into a reviewable manifest with
``confidence``, ``reason`` and the resolved ``fiscal_year`` per candidate:

* 8-K + Item 2.02 → high; other 8-Ks only with ``include_low_confidence``.
* 6-K → high only when an EX-99 exhibit's description/filename looks like an
  earnings release (metadata-only selection, capped index checks).
* ``start_year``/``end_year`` are **FISCAL years** (the ``reportDate`` year, with
  a filing-year fallback when ``reportDate`` is empty); the EDGAR fetch window is
  widened by one year so a fiscal-year-N report filed in N+1 is still found.
  ``fiscal_year``/``fiscal_quarter`` narrow to an exact period. Selection is
  never period identity — the period agent still decides the reporting period.

`run_backfill()` invokes the existing graph once per filing in
`quarterly_backfill_only` mode. The period agent still classifies the filing
(the only source of period identity), but an annual result is skipped at
`check_period` before concept loading, extraction, and saving. The post-save Q4
node is bypassed entirely for every backfill run. Resume needs **no extra
collection**: each saved value already carries ``accession_number``, so
``processed_accessions(cik)`` reads ``concept_values_quarterly`` and
``concept_values_annual`` and treats a candidate whose accession is present as
already processed. ``--resume`` skips those, ``--reload`` re-runs them, and a
read outage degrades to redundant work rather than lost data. **Nothing in the backfill deletes** — a re-run relies on the pipeline's
existing atomic write-first period replace, so an interrupted reload never leaves
a period empty. The manifest is newest-first and a default backfill processes
newest → oldest; ``--oldest-first`` reverses only the order of eligible
quarterly candidates (it never processes annual periods or derives Q4).

Progress presentation is shared: ``cli/run_ui.py`` holds ``RunPresenter`` and the
step-summary helpers, and BOTH the multi-ticker CLI and the backfill CLI use it.
A backfill therefore renders the same Rich spinner + progress bar, ``▶ stage``
markers, ``[period] ✓`` / ``[agent pipe] concepts:`` step summaries,
``[llm]``/``[tool]``/``[db]`` lines, and ``saved ✓ (N LLM calls) (FY… Q…, N concept(s))``
footer, with one progress row per filing (``[i/N] <accession>``). ``--quiet``
suppresses the per-call lines; ``--verbose`` adds DEBUG logging. The runner
installs/clears the thread-local ``hooks`` callbacks around each graph invocation.

Live dry-run validation: ASML fiscal years 2025–2026 yields 6 high-confidence 6-K
candidates (FY2025 Q1–Q4 + FY2026 Q1–Q2), and FY2024 yields 4 — the FY2024 annual
(filed 2025-01-29) is correctly excluded from a 2025-and-later fiscal selection.
TSM yields 0 because its earnings exhibit filenames are opaque — the
pinned-accession path is the intended route.

## 6. Phase 6 staging pilot

`NORMALIZE_DB_NAME` is now configurable (default `normalize_data`) so the
application can point at a dedicated isolated staging database without changing
production defaults. `scripts/phase6_6k_staging_pilot.sh` requires an explicit
`STAGING_MONGODB_URI`, a database name containing `staging`, and an additional
`PHASE6_CONFIRM=YES` before it will run the two pinned live extractions. Its
default mode performs only read-only DB preflight and accession-pinned CLI
dry-runs. The checklist and exact commands are in
[`phase6_6k_staging_pilot.md`](phase6_6k_staging_pilot.md).

No staging URI is configured in the current environment, so the live writes and
production rollout are intentionally not executed by this implementation pass.

## 7. Read-only ASML / TSM concept check

A read-only query of the configured `normalize_data` database confirmed that both pilot companies currently need the Phase 1 bootstrap:

| Ticker | CIK | Annual concept rows | Annual statements (income / balance sheet / cash flow) | Quarterly concept rows | Annual `form_type` values |
|---|---:|---:|---:|---:|---|
| ASML | `0000937966` | 305 | 77 / 117 / 111 | 0 | 277 `20-F`, 28 `20-F/A` |
| TSM | `0001046179` | 466 | 123 / 159 / 184 | 0 | 466 `20-F` |

The annual rows include IFRS, US-GAAP, issuer-specific concepts, custom grouping rows, and dimensional/member rows. The copy must therefore include **all concept rows across all three statements**, not just standard concepts or income. ASML has parent-ID references on 177 rows and dimensional `concept_id` references on 98; TSM has 280 and 159 respectively. Every inspected reference pointed to a concept row in the same company's annual collection. Preserving `_id` and all metadata therefore keeps those references valid in the copied quarterly collection. TSM has one annual row with no path; the bootstrap preserves it rather than inventing a hierarchy path.

An existing quarterly example (MSFT) uses `form_type="10-Q"`, while ASML/TSM annual concepts use `20-F`/`20-F/A`. The bootstrap's `form_type="10-Q"` change matches the existing quarterly concept schema. The actual SEC source form of an earnings release (such as `6-K`) must be tracked separately on filing/value provenance when that phase is implemented.
